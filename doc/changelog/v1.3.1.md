# 墨笺 1.3.1

## 新增

- **标题栏快速切换主题**：标题栏新增调色板图标，点开下拉即可在内置浅色 / 深色 / 跟随系统与全部扩展主题之间切换；顶部显示当前主题，扩展主题按文件分组并附明暗与作者 / 来源信息，选中项打勾。菜单里的每一项都走 `set_active_theme`，切换效果、`theme_extension.toml` 持久化与「设置 → 外观」完全相同；底部「主题设置…」直接跳到外观页。菜单与工作区 / 通知浮层互斥，点击外部自动关闭，列表限高 320px、带常驻独立滚动条，主题再多也不会把行压叠在一起；暂无扩展主题时给出提示。
- **扩展主题按主题文件分层管理**：设置 → 外观的「当前激活的主题」改为按文件分组的层级列表：内置主题一组，每个扩展主题文件一组；组标题显示该文件包含的主题数与折叠箭头，点击可折叠 / 展开，也可一键「全部折叠 / 全部展开」，组内缩进列出各个主题变体，当前选中的主题仍打勾。一个主题文件现在可以包含多个主题：用 `[collection]` 定义主题集名称与作者 / 来源，再用多个 `[[themes]]` 小节定义变体，颜色、圆角、语法高亮分别写在 `[themes.colors]`、`[themes.radius]`、`[themes.highlight]`（含 `[themes.highlight.syntax]`）下；集合级元信息由变体继承，变体 id 为「文件名-变体名」（重名自动加序号），总配置里写成 `active = "ext:<id>"`。旧的单主题 `[theme]` + `[colors]` 文件与既有 `ext:<id>` 配置继续按原规则载入，无需迁移。
- **Zed 主题导入保留文件层次**：导入 Zed 的 `.json` 主题（或直接放进主题目录）时，同一个文件里的明暗等多个变体会转换进**一个** TOML 文件，在设置页与标题栏菜单归到同一分组，不再拆成一堆平铺文件；原 JSON 保留，重复导入自动加序号避免覆盖，目录里的 JSON 只在转换结果缺失或比它更旧时重新生成，不会每次扫描都重写。「生成示例主题」改为生成带完整注释、含明暗两个变体的 `[collection]` / `[[themes]]` 模板。主题载入 / 变化 / 移除通知按文件聚合，一个多主题文件只提示一次，载入提示里显示变体数。
- **MCP 审计页翻页**：设置 → MCP → 审计改为每页 100 条、最多 10 页，提供「上一页 / 下一页」按钮与「第 x / y 页」指示，首页 / 末页按钮自动禁用；只加载可展示的最近 1000 条，更早的调用记录既不读取也不展示，换页时列表 id 随之变化、滚动位置回到顶部。审计内容与写入规则不变，仍不记录笔记正文。
- **右键「复制名称」「复制全名称」**：标签页与笔记树（笔记本 / 文件夹 / 笔记）的右键菜单、行尾「…」菜单同步新增两项。「复制名称」只写入该对象的显示名：笔记不带 `.md` / `.markdown` 扩展名，名称中间的点（如「v1.2 计划」）保持不变；「复制全名称」按「笔记本/文件夹/笔记」用 `/` 级联，笔记本位于层级顶端时与名称相同，外部文件与官方只读文档没有笔记本层级时退化为名称本身。复制走系统剪贴板并提示「名称已复制到剪贴板」，不影响笔记树内部原有的「复制 / 剪切 / 粘贴」条目；官方只读文档仍不提供「复制路径」「打开所在文件夹」。

## 优化

- **崩溃记录覆盖 Windows 原生异常**：panic hook 只覆盖 Rust panic，访问冲突、栈溢出等原生异常此前不会在 `crashes/` 留下任何记录。启动时现在额外注册最前置的 vectored exception handler，把异常码与地址写成同一格式的 `crash-*.json`（`native: true`，backtrace 标注不可用），可沿用既有的待上报 / 清理与上报流程；调试器输出、断点、C++ first-chance 异常不算崩溃，一次进程只写一条，异常继续交给系统与 WER 处理，不改变崩溃行为。非 Windows 平台为空实现。

## 修复

- **主题列表滚轮带动整个设置面板**：外观设置页的主题列表原先是嵌在可滚动页面里的 `max_h` 平铺容器，固定行高被 flex 压缩、没有滚动余量，滚轮还冒泡到外层设置页，表现为「滚轮翻的是外观面板，主题列表纹丝不动」。现在改为固定 238px 视口的独立滚动区，行高固定、内容层不被压缩，配常驻垂直滚动条，并在捕获阶段由列表先消费滚轮：鼠标停在列表上时先翻主题，滚到边界后才把滚轮交回设置页；主题很少或指针移出列表时仍可正常滚动设置页。折叠 / 展开分组后行数与滚动位置同步更新。
- **调试构建打开外观设置时主线程栈溢出**：Windows 主线程默认栈只有 1 MiB，debug 构建里 GPUI 渲染设置 → 外观页的调用链会超出这个上限，触发 `0xC00000FD` 栈溢出，且 panic hook 来不及运行、`crashes/` 里没有任何线索。MSVC 构建现在通过 `/STACK:8388608` 把 PE 头的栈保留大小提到 8 MiB；配合原生异常记录，即使再遇到同类崩溃也会留下含异常码 / 地址的 `crash-*.json`。

## 其他

- **升级须知（Zed 主题文件）**：对于含多个变体的 `.json`，v1.3.0 由目录内 JSON 自动转换生成的分体文件（如 `<名称>-zed-1.toml`）不会自动删除或合并；升级后首次扫描会为同一 JSON 另生成一份包含全部变体的 `<名称>-zed.toml`，旧文件仍各自成组，列表里会出现重复主题。若不想看到重复项，可删除旧的分体 TOML（原 JSON 保留）；`active` 若指向旧文件，请在设置页重新选一次主题。手工写的旧单主题格式不受影响。
- **配置与文案**：`theme_extension.toml` 头部注释补充 `[collection]` / `[[themes]]` 写法与变体 id 规则，设置页提示改为说明按文件分组、可折叠与列表独立滚动；新增标题栏主题菜单、分组标题与变体数量、全部折叠 / 展开、审计翻页、复制名称等中英文文案，`doc/mcp.md` 的审计说明同步标注每页 100 条、最多 10 页。
- **回归测试**：新增单文件多主题（`[[themes]]`）解析与变体 id / 分组、Zed 多变体保持同一文件并共享集合信息、示例主题可载入、主题生成结果仍兼容组件库 `ThemeConfig`、旧单主题格式不受影响、原生异常记录可被待上报流程识别、审计分页上限、名称 / 级联全名称解析（带点名称、`.markdown` 扩展名、外部文件与官方只读文档退化为名称），以及主题列表滚轮优先与标题栏菜单 `max_h` 下行高不被压缩等用例。本地验证：`cargo test -p mdwork-core --lib`（123 项）、`cargo test -p md-work-gui --bin md-work`（60 项）全部通过，`cargo check --workspace` 通过。
