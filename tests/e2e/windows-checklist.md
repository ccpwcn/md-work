# Windows 手工验收清单（v1.2.6）

本清单覆盖自动化测试无法验证的 GUI 与系统集成行为。执行环境建议是一台干净的 Windows 10/11 x64
（非开发机），使用普通用户账户。

标记约定：`[ ]` 未执行，`[x]` 通过，`[!]` 失败（附日志与截图）。

## 1. 安装与卸载

- [ ] 以普通用户运行 `dist/md-work-1.2.6-setup.exe`，全程不出现 UAC 提权提示。
- [ ] 安装目录为 `%LOCALAPPDATA%\Programs\md-work`，开始菜单与桌面快捷方式出现“墨笺”。
- [ ] 安装目录（exe 同目录）存在 `changelog.md` 与 `mcp.md`，文件属性为只读；zip 解压版同样存在这两份文件且默认只读。
- [ ] “应用和功能”中可见“墨笺 md-work 1.2.6”（DisplayName），DisplayVersion 为 1.2.6，大小合理（> 20 MB）。

- [ ] 启动后标题栏显示“墨笺”，任务栏图标为墨笺图标，无白边或模糊。
- [ ] 缩放 125% / 150% 时界面清晰（PerMonitorV2），移动窗口到不同缩放显示器后字体不模糊。
- [ ] 卸载后程序目录、开始菜单与桌面快捷方式被移除，`%LOCALAPPDATA%\md-work`（配置/日志）与笔记保留。
- [ ] 卸载不修改 `.md` 默认应用。

## 2. 首次启动

- [ ] `%USERPROFILE%\Documents\md-work` 被创建，包含 `.mdwork/workspace.toml` 与示例笔记本“我的笔记本”。
- [ ] `%LOCALAPPDATA%\md-work\config\` 下生成 `core.toml`、`runtime.toml`、`theme.toml`，均带有可读注释；
  删除整个 `config\` 目录后仍能启动并重新生成。
- [ ] 示例笔记“欢迎使用墨笺.md”可打开、编辑、保存。
- [ ] 关闭再启动，窗口位置/大小、面板停靠、主题、语言保持。
- [ ] 拖动侧栏与正文之间的分隔条可调整宽度并立即生效，双击恢复默认宽度；设置 → 面板中的“窄/标准/宽”预设与当前宽度同步高亮，重启后宽度保持。
- [ ] 五个面板（笔记/大纲/搜索/书签/回收站）可分别设为左侧或右侧并各自保留停靠与宽度；纵向布局下内容从顶部开始排列，不再垂直居中。
- [ ] 切换工作区：选择空文件夹会创建新工作区；选择已有工作区直接打开；选择非空且非工作区的文件夹时提示风险且默认选项为“否”。
- [ ] 工作区下拉框中同名但路径不同的文件夹（如 `D:\work` 与 `E:\work`）显示完整路径以便区分。
- [ ] 手工把 `config\runtime.toml` 中某个非核心键改成非法值后启动，界面提示具体文件与键名，应用仍可正常使用；改回或删除该键后提示消失。
- [ ] 设置页左下角显示“墨笺 1.2.6 · MIT”，与安装包版本一致。
- [ ] 新版本首次启动自动以预览模式打开 `v1.2.6 更新说明`；标签显示“官方 · …”，状态栏显示“官方发布文档 · 只读”，不能切换到编辑模式、`Ctrl+S` 与「另存编码」都提示“官方发布文档不允许编辑修改”。
- [ ] 关闭这份更新说明标签后重启，不再自动打开；`config\runtime.toml` 的 `shown_changelog_version` 变成 `1.2.6`。把该值改回空字符串再启动，又会打开一次。
- [ ] 会话中不残留官方说明文档：退出时若更新说明仍开着，重启后不会以可编辑外部文档的形式恢复。
- [ ] 设置 → MCP 点击「使用详细说明」：设置面板关闭，并以预览模式打开 `mcp.md`（同样只读）。
- [ ] 用记事本改动安装目录里的 `changelog.md` 或 `mcp.md` 后启动，弹窗提示“此文件已被修改，不是官方权威版本，请仔细甄别，或联系软件作者。”；文档内容仍是官方原始内容，磁盘文件不会被程序写回。
- [ ] 第二次启动 `md-work.exe <某个.md>` 时不会新开进程，而是把路径交给已运行实例打开。

## 3. 编辑与保存

- [ ] `Ctrl+S` 保存；标题星号消失；状态栏显示“已保存”。
- [ ] 选中文字后 `Ctrl+B` / `Ctrl+I` / `Ctrl+K` 分别包裹为粗体、斜体、链接；无选区时插入成对标记且光标位于中间。
- [ ] 编辑后 2 秒内出现“未保存”标记；自动保存开启时落盘。
- [ ] 编辑器内 `Ctrl+F` 打开查找栏、`Ctrl+H` 打开替换栏，可循环查找并替换单个/全部。
- [ ] 预览中的代码块显示语言标签、语法高亮与“复制”按钮；复制内容为代码正文；长行可在换行/横向滚动间切换。
- [ ] 用 `md-work.exe <工作区外的.md>` 打开外部文件，标签显示“外部 · 文件名”且出现“存入笔记本”；点击后当前笔记本新增该笔记（同名自动加序号），外部原文件保持不变。
- [ ] 用外部编辑器改写同一文件后再切回墨笺，出现磁盘冲突提示，可选择重新加载或保留本地。
- [ ] 行尾 CRLF 的笔记保存后仍为 CRLF；LF 仍为 LF。
- [ ] GBK 编码的 `.md` 打开不乱码，保存后仍为 GBK；可用“另存编码”改为 UTF-8。
- [ ] 关闭有未保存修改的窗口时提示保存。

## 4. 崩溃恢复

- [ ] 编辑某笔记但不保存，等待 2 秒让快照写入，然后任务管理器结束进程。
- [ ] 重新启动后出现“恢复未保存的编辑”对话框，条目包含笔记名与“刚刚/几分钟前”。
- [ ] 点“恢复”后笔记重新打开并载入快照内容，状态为未保存；手动保存后快照文件被删除。
- [ ] 点“丢弃”后快照删除，笔记内容不被改动。
- [ ] “全部丢弃”清空所有快照并关闭对话框。

## 5. 搜索 / 书签 / 大纲 / 命令面板

- [ ] 搜索面板可切换 `Aa`（区分大小写）、`.*`（正则）、`文件名`，结果数量随之变化。
- [ ] 点击搜索结果跳转到对应笔记与行。
- [ ] 为笔记与标题添加书签，重启后书签仍在，点击可跳转。
- [ ] 大纲面板随光标/预览位置高亮。
- [ ] `Ctrl+Shift+P` 打开命令面板，输入可模糊过滤，`↑/↓` 选择，`Enter` 执行，`Esc` 关闭。

## 6. 导出

- [ ] 导出 PDF：中文、表格、代码块、数学公式、图片均正确；页边距/字号/行高/页码设置生效。
- [ ] 导出 PNG：输出清晰，宽高比正确。
- [ ] 目录深度与图片宽度选项生效；两端对齐开关生效。
- [ ] 导出过程中可取消，界面不卡死。

## 7. 整本打包

- [ ] “导出笔记本”生成 `.zip`，解压后目录结构与笔记一致，含 `manifest.json`。
- [ ] 导入该 `.zip` 时展示冲突预览；`保留两者` 不会覆盖原文件。
- [ ] 导入包含 `..\`、绝对路径、符号链接或超大文件的 zip 被拒绝并给出清晰错误。
- [ ] 导入 5 万文件 / 2 GB 上限的边界行为符合提示。

## 8. 图片

- [ ] 粘贴/插入本地图片写入当前笔记本 `assets/`，Markdown 引用为相对路径，预览可见。
- [ ] 配置 HTTP 图床后上传成功且写回 URL；失败时提示且不破坏笔记。
- [ ] 图片写入路径不能逃逸到笔记本之外。

## 9. MCP（HTTP）

在设置 → MCP 生成令牌并启用服务后：

- [ ] `curl -i http://127.0.0.1:11026/mcp` 无令牌返回 401。
- [ ] 带错误令牌返回 401。
- [ ] 带正确 `Authorization: Bearer <token>` 的 `initialize` 请求返回 200 与服务器信息。
- [ ] 服务仅监听 `127.0.0.1`（`netstat -ano | findstr 11026` 显示 `127.0.0.1:11026`）。
- [ ] 未授权笔记本的读取返回 403；被 glob 拒绝的路径返回 403。
- [ ] GUI 中有未保存修改的笔记，MCP 写入返回冲突错误，GUI 缓冲区未被覆盖。
- [ ] 关闭 MCP 开关后端口释放；令牌重启后仍有效（DPAPI）。
- [ ] 审计 JSONL 追加记录，且不包含笔记正文。
- [ ] `md-work-cli mcp serve --stdio` 可被 MCP 客户端（如 Claude Desktop）拉起并完成 `tools/list`。

## 10. CLI

- [ ] `md-work-cli notebook list --json` 输出合法 JSON。
- [ ] `md-work-cli search "关键词" --regex` 命中正确。
- [ ] `md-work-cli notebook export/import` 与 GUI 生成的 zip 互通。

## 11. 异常与边界

- [ ] 工作区目录被删除或改名后启动，不崩溃并给出可恢复的提示。
- [ ] 笔记本只读时保存失败有明确提示，编辑内容不丢失。
- [ ] 超长路径（> 260 字符）的笔记可创建/打开（需系统启用长路径支持）。
- [ ] 无网络时启动、编辑、导出正常；图床上传失败仅提示。
- [ ] 日志位于 `%LOCALAPPDATA%\md-work\logs\md-work.YYYY-MM-DD.log`，不包含笔记正文。
- [ ] 开发构建下设置环境变量 `MDWORK_TEST_PANIC=1` 启动，`%LOCALAPPDATA%\md-work\crashes\` 生成 `crash-*.json`，
  设置 → Windows 的“打开崩溃记录”可定位该目录；记录不含笔记正文。
- [ ] 未配置 Gitee 令牌时，存在历史崩溃记录也不会发起网络请求，日志记录“已跳过”。
- [ ] 在 `config\runtime.toml` 的 `[crash_report]` 填入令牌并保持网络可用后启动，Gitee 仓库出现对应 Issue，
  本地记录改名为 `crash-*.json.reported` 且不会重复上报。
- [ ] 令牌无效或断网时启动不受影响，失败原因写入日志。

## 12. 性能冒烟

- [ ] 含 2000 篇笔记的笔记本可在大约 3 秒内打开并展开目录。
- [ ] 1 MB 的 Markdown 文档编辑输入无明显卡顿，预览切换 < 2 秒。
- [ ] 全工作区搜索 5000 篇笔记在 5 秒内返回首批结果。
